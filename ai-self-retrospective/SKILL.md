# AI 自我复盘与反向研究

面向产品经理（皮玺玉）的自我研究类任务：AI 基于真实工作痕迹（文件/日报/周报/月报/handoff/坑库/述职），反向研究本人，产出结构化《自我研究报告》。典型触发：月度/季度自我复盘、述职前的能力盘点、"帮我分析下我的优缺点"、"我还有什么知识要补"。

## 核心铁律

1. **禁止编造**：所有成就/数字/缺口必须来自真实文件扫描（handoff、日报、周报、月报、坑库、述职、技能索引）。拿不到写"待确认"，不猜测。
2. **区分事实与判断**：成就是可验证的事实（文件路径/数字），不足是分析判断（标注置信度）。
3. **报告落盘**：`D:\AI\AI产品工作\本机\自我研究报告_YYYYMMDD.md`。
4. **完成后更新 handoff.md**：追加 ✅ 标记 + 3-5 条关键发现。

## 数据源（按优先级）

1. `本机\handoff.md` — 当前任务/已完成/踩坑（第一手）
2. `本机\坑库.md` — 踩过的坑（K001+，5 要素）→ 不足的实证
3. `汇报\daily\`（25 篇日报）、`weekly\`（周报）、`monthly\`（月报 179 项产出）— 工作量与方向
4. `本机\述职报告_深化版_*.md` + 飞书述职云文档 — 自我认知口径（五章）
5. `技能\技能索引.csv`（298 条）+ `技能\skills\`（306 目录）— 能力资产盘点
6. `产品经理工作复盘报告_*.md` — 全盘扫描的量化锚点
7. `hermes-home\agents.md` — 全局协作约定（画像/坑库/效果分级/项目清单）

## 报告结构（7 章）

1. **成就盘点（实证）**：按资产分组（交付/技能/流程/自动化/治理），每条带路径与数字。示例口径：306 技能/298 索引、179 项月产出、P01-P08 三尺寸验收、129 条验收清单。
2. **方法论识别**：PRD 驱动（提示词→目标→PRD）、技能沉淀→治理→平台化、handoff 连续性、汇报自动化、坑库反模式。
3. **不足与缺口（分级）**：
   - 工程级（Phase 0 门禁、六维评分、签核、证据链 E1-E6、追溯矩阵）
   - 方法论级（踩坑未制度化——已补坑库；技能命中率未量化；模型依赖；沉淀多于验证）
   - 知识级（从坑库 K 编号 + 工作痕迹反推：git/工作树/钩子、数据统计、竞品分析等）
4. **可技能化候选**：日常工作中反复出现的动作 → 建议封装为技能/工作流（见"技能化提醒机制"）。
5. **知识补齐清单**：当前缺什么（技术/流程/领域），按"影响-紧迫度"排序。
6. **工作复盘**（阶段性）：目标 vs 结果、原因分析、下一步。
7. **情绪复盘与深度剖析**（可选，用户要求时）：
   - 情绪复盘：最近的高点/低点事件、触发点、应对模式、可复用策略（如"并行工作流偏好"带来的压力点）
   - 深度剖析：行为模式（快速行动 vs 深度验证的张力）、决策风格（数据+直觉）、风险偏好、成长阶段判断

## 技能化提醒机制（日常）

每次会话中，当出现以下信号时，AI 应主动提醒并记录到 `本机\技能化候选清单.md`：
- 同一个操作/流程出现 ≥2 次（如"又要整理文件""又要扫描目录"）
- 用户表达了"好麻烦/重复/又忘了"情绪
- 发现新工具/新方法解决了一个之前费时的问题
- 坑库新增 K 编号，且该坑的规避动作可流程化
- 用户提到"网上看到 X 效果/方法"且想复用

清单格式：
```markdown
## [日期] 候选
- [候选名]：反复动作描述 | 触发信号 | 建议封装（技能/工作流/脚本） | 状态（待确认/已确认/已封装）
```

## 验证

- 报告中每个成就数字可溯源到真实路径（抽查 2-3 条）。
- 坑库 K 编号与不足分析对应（如 K012 → 效果分级制度 → 不足：探索投入过度）。
- 报告落盘 + handoff 更新都完成才算收尾。
