# 产品工程SOP：飞书→墨刀原型工作流

## 角色与职责

| 角色 | 职责 | 工具 |
|------|------|------|
| PM | 在飞书提需求、确认原型方向、决策反馈 | 飞书、墨刀预览 |
| 设计师 | 在墨刀微调原型、留反馈 | 墨刀编辑器 |
| Hermes | 拉取PRD、分析需求、生成原型 | lark-cli、墨刀MCP |

## 标准操作流程

### Step 1: PM在飞书提需求
- 在PRD文档中写清功能描述、用户场景、页面预期
- 标记状态为「待设计」

### Step 2: 触发原型生成
对Hermes说：
> "帮我把这个飞书PRD生成墨刀原型 https://xxx.feishu.cn/docx/xxxxxx"

Hermes自动执行：
1. `lark-cli docs +fetch` 拉取PRD内容
2. 分析提取页面结构和交互需求
3. `mcp__modao__generate_html` 生成原型
4. 返回预览链接

### Step 3: 预览确认
- 打开预览链接在浏览器查看
- 确认大方向（布局、页面数量、核心功能）
- 不满意可要求重新生成或调整参数

### Step 4: 移入团队空间
- 墨刀APP → 个人空间 → 找到生成的文件
- 右键 → 移动到 → 选择团队空间对应项目

### Step 5: 团队审阅与反馈
- 设计师在墨刀中查看和微调
- **反馈统一回到飞书PRD文档评论区**（墨刀无评论API）
- 评论格式：🔴重做 / 🟡调整 / 🟢建议

### Step 6: 迭代
- Hermes读取飞书评论，汇总反馈
- 基于反馈重新生成原型v2
- 循环至通过

## 质量门禁

| 检查点 | 通过条件 | 负责人 |
|--------|---------|--------|
| PRD完整性 | 有明确页面描述和用户场景 | PM |
| 原型方向 | PM确认布局和核心功能正确 | PM |
| 设计细节 | 设计师无🔴级反馈 | 设计师 |
| 可交付 | 所有🔴🟡反馈已处理 | PM |
